## Encoding, data and evaluation

Final RQ1 uses one Bloom vector per composite record. It normalizes description, dosage, dosage form, and pack size individually, joins them with `|`, and encodes distinct underscore-padded bigrams with indexed HMAC-SHA256. The encoder takes the first four digest bytes modulo `l` with the configured research key. Description-only remains an RQ1 ablation. Dosage contributes text to the composite and produces no separate deterministic token. RQ2 encodes the composite victim and dictionary records with the same encoder. Its bit-frequency analysis uses the positions generated by that encoder.

Primary RQ2 `precision`, `recall`, and `f1` use RQ1's unordered pairs from connected-component clusters. Bloom edges use `Dice >= tau`. Empty predicted and true pair sets yield 1 for all three scores. The separately named `cross_party_*` scores evaluate direct clean-by-noisy representative pairs with a zero convention for empty denominators. Existing FPR, AUC, and `*_unc` columns describe the cross-party evaluation. Primary RQ2 exact linkage uses normalized SHA-256 as in RQ1. The RQ2 token privacy comparison retains HMAC-SHA256. Both raw and normalized SHA-256 baselines are covered by the RQ1 golden.

The three current experiment drivers use the final RQ1 prepared records, saved entity splits, and pre-generated noisy variants. The loader aligns noisy rows to the clean order using stable record IDs and rejects membership or truth mismatches. RQ2 representatives inherit those entity splits, and its victim sampling uses stored noisy variants. Default preparation edits only `raw_item_description`. The `--all-fields` preparation option uses the separately versioned `data/generated/noisy_all_fields_v1` directory. The original prepared and noisy artifacts have an empty diff against `eed1ccd`.

Shared locations are under `backend/app/src/common/`.

| --- | --- | --- |

| Legacy RQ1 generators and RQ2 inline noise | `noise/typo_noise.py:inject_noise` serves preparation. | RQ1 samples `round(p*n)` distinct records, applies one or two typos and protects numeric spans. Prior inline RQ2 applied length-proportional edits. |
| RQ2 normalization and composite assembly | `preprocessing/normalizer.py:normalize` and `field_builder.py:build_field_strings`. | Adopted RQ1 NFKC, case folding, Unicode letters/digits and explicit composite separators in place of RQ2's NFKD and ASCII cleanup. |
| RQ2 q-grams and encoder | `encoding/qgrams.py:extract_qgrams` and `encoding/bloom_filter.py:BloomFilterEncoder`, including `grams`, `gram_positions` and `fill_ratio`. | Adopted RQ1 padded indexed HMAC with a configured key. Historical RQ2 used unpadded grams, a seed-derived key and coprime-step double hashing. The shared formula accepts positive lengths and allows repeated positions when `k > l`. |
| RQ2 Dice matrix | `similarity/dice.py:dice_matrix` and `compute_similar_pairs`. | Common binary Dice preserves the zero empty-filter score and supports both rectangular matrices and unordered pairs. |
| RQ1 embedded tau grid and RQ2 direct thresholding | `linking/threshold.py:threshold_values`, `tune_tau` and tau selection, plus `linking/clustering.py` and `experiment/linkage.py:evaluate_bloom_linkage`. | RQ1 retains single and per-level cutoff policies. RQ2 and RQ3 use the shared per-noise cluster evaluation. RQ2's direct matching retains its secondary FPR-constrained thresholds. |
| HMAC exact tokens and RQ2 PRF arithmetic | `linking/exact.py:ExactLinker` and `keyed_sha256`; `evaluation/metrics.py:pairwise_prf` and `evaluate_clusters`. | The two pair definitions use the same count-based arithmetic with explicit empty conventions. |
| RQ2 analyzer's Holm, interval, pairing and effect helpers | `evaluation/aggregation.py:holm_adjust`, `mean_ci95_half_width`, `paired_seed_differences` and `paired_effect`. | Each RQ retains its hypothesis families and test directions. |
| RQ2 Python defaults, seeds, CSV and grid code | `config.py:load_config`, `seeding.py:make_rng`, `experiment/io.py` and `experiment/runner.py:iter_grid`. | Active research defaults come from YAML. RQ2 output metadata records the selected axes and dataset variant. |
| RQ2 NumPy randomized response and DP ablation | `encoding/randomized_response.py` and `experiment/dp_sweep.py` serve RQ3 and RQ2's optional privacy companion. | Both paths use the same record encoding and primary utility evaluation at each epsilon. |

Removed files include RQ2's `bloom_encoder.py`, `qgram_utils.py` and `text_normalizer.py`, the retired `common/noise_injection.py`, and the old location of `numpy_randomized_response.py`. Removed definitions include the RQ2-local Dice and PRF formulas, the legacy controlled-noise loader, and the legacy RQ1 inline mutation methods. The former RQ1 generator command delegates to canonical preparation. The historical RQ1 grid still replays existing character-rate files and retains its legacy serving defaults for that replay.

## Proposed behaviour changes (not applied)

- Define a migration strategy for the serving encoder and existing stored vectors. Serving uses field-tagged per-token q-grams, an environment-backed key and default `q=3`. It hashes `qgram:index` and uses eight digest bytes. Research uses a joined composite string, `q=2`, `index:qgram`, and four bytes. The serving resolver uses a streaming representative, which differs from research connected components.
- Review the sign-count effect labeled `rank_biserial` before switching to a signed-rank-weighted effect. The existing calculation moved without a numerical change.
